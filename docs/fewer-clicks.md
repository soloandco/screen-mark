# 클릭 흐름 검토와 개선

검토일: 2026-10-29. 비교 대상: v1.1.0과 v1.2.0. 실제 실행 기록은 [v1.2.0 검증 결과](interaction/v1.2.0.json)에 둔다. 일반 UI의 포커스·입력·에러 피드백은 [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)를 참고하고, 아래 클릭 수는 이 앱의 실제 버튼·제스처 흐름에서 계산했다.

## 같은 결과에 필요한 동작

클릭은 버튼을 누르는 동작으로 센다. 드래그 한 번은 별도 동작으로 표시한다. 키보드 대체 동작과 파일 선택창도 구분한다. 사용자 전체의 평균 작업 속도를 측정한 자료는 아니다.

| 작업 | v1.1.0 | v1.2.0 | 줄인 단계 |
|---|---|---|---|
| 영역 캡처 후 편집 시작 | 확장 아이콘 클릭, 영역 메뉴 클릭, 드래그, 확인 클릭 | 확장 아이콘 클릭, 영역 메뉴 클릭, 드래그 | 클릭 3회에서 2회. 드래그는 동일 |
| 사각형 도구로 작업하다 번호 위치 조정 후 계속 그리기 | 선택 도구 클릭, 번호 드래그, 사각형 도구 클릭 | Ctrl/⌘를 누른 채 번호 드래그 | 도구 클릭 2회 생략 |
| 클립보드 이미지 열기 | 파일로 저장한 뒤 이미지 열기와 파일 선택 | 편집기에서 Ctrl/⌘+V | 파일 저장·선택 과정 생략 |

박스와 번호를 한 번에 추가하는 기본값과 Ctrl/⌘+C 복사는 이미 제공하므로 유지했다. 드래그마다 자동 복사하는 방식은 사용자가 편집을 끝내기 전에 클립보드 내용을 바꿀 수 있어 채택하지 않았다. 확장 아이콘을 누르자마자 무조건 캡처하는 방식도 세 캡처 방식의 선택을 어렵게 해 채택하지 않았다.

## 선택과 복구

- **드래그 후 바로 편집**이 기본이다. 체크를 끄면 여러 번 다시 드래그한 뒤 버튼 또는 Enter로 확정할 수 있다. 이 선택은 브라우저에 기억한다.
- 너무 작은 드래그는 편집기로 이동하지 않는다. 자동 확정이 실패하면 임시 원본과 선택을 보존하고 확인 버튼으로 재시도할 수 있다.
- Ctrl/⌘ 선택은 번호·텍스트 도구에서도 추가 동작보다 먼저 처리한다. 기존 표시만 옮기고 현재 그리기 도구는 유지한다. 이동은 Undo로 되돌릴 수 있다.
- 이미지 붙여넣기도 기존 파일 열기의 형식·크기·해상도 검사, 로딩 잠금과 미저장 표시 확인을 사용한다. 텍스트 입력란과 텍스트 대화상자에는 개입하지 않는다.
- 클립보드 읽기 권한, 서버 전송, 새 런타임 의존성을 추가하지 않았다.

## 검증 범위

별도 Chrome 155 시험 프로필에서 자동·수동 영역 선택, 실제 PNG·클립보드 이미지, modifier 이동·Undo, 일반 그리기 재개, 텍스트 붙여넣기, 지원하지 않는 입력, 저장 충돌 후 붙여넣기 취소, 초기 이미지 로딩 중 붙여넣기를 검증한다. 영역 선택은 1배·2배 배율에서 검사한다. 테스트는 사용자 프로필을 열지 않는다.

실제 Ctrl+V로 OS 클립보드 이미지를 붙여넣고, PNG로 다시 내려받아 원본 픽셀을 확인했다. 지원하지 않는 SVG 입력은 합성 paste 이벤트로 파일 검증 경로를 검사했다. Windows의 실제 Ctrl 동작을 실행했으며, Mac의 Command 하드웨어 조작은 직접 검증하지 않았다. 사용자 Chrome의 메뉴 지연은 이번 변경으로 해결했다고 주장하지 않는다.
