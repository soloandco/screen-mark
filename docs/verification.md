# Screen Mark 검증 기록

기준일: 2026-10-21. 초기 검증 대상: 이 프로젝트 `extension/`의 로컬 확장 v1.0.1. 자동 검증은 별도 테스트 프로필에서 진행함. 이후 사용자가 자신의 Chrome에 설치하고 정상 동작을 확인함. v1.0.2와 v1.0.3의 추가 검증은 아래에 별도 기록함.

## 확인 결과

- `npm test`: 모델 테스트 10개 통과. 역방향 사각형, 확대 좌표, 번호 증가, undo/redo, 이력 격리, 선택, 이동, crop, 전체 페이지 크기 제한 확인.
- Node coverage 기준 `extension/model.js`의 line coverage 100%, branch coverage 91.43%. 이 수치는 모델 파일만의 범위이며 확장 전체 커버리지는 아님.
- `node tests/mutation.mjs`: 임시 사본에서 undo를 무력화하면 번호·이력 회귀 테스트가 실제로 실패함을 확인. 원본 파일은 변경하지 않음.
- `node tests/browser.mjs`: 별도 임시 Chromium 프로필에서 실제 확장을 로드해 통과. 원본 매니페스트를 변경하지 않고 CDP `Extensions.triggerAction`으로 activeTab을 부여함.
- 사각형 및 원형 숫자 1·2를 추가한 PNG를 내려받아 실제 픽셀과 원본 해상도를 대조함.
- 번호 자동 증가, 실행 취소·다시 실행, 선택·이동·삭제, 편집 정보 새로고침 복원 확인.
- 화살표, 텍스트 입력 대화상자, 모자이크 추가, 실제 클립보드 이미지 쓰기 성공 확인. 다른 외부 앱으로 붙여 넣기는 미확인.
- 캡처 메뉴가 현재 화면·스크롤 전체 페이지 두 개만 제공되는지 확인. 클립보드 복사를 기본 버튼으로 변경하고 Ctrl+C로 합성 이미지를 복사하는 실제 브라우저 테스트 통과. 단축키 미구현 상태에서 같은 테스트의 실패를 먼저 확인함.
- 자르기 후 PNG 크기 720 × 500px 확인.
- 실제 현재 화면 캡처 1440 × 1000px, 스크롤 전체 페이지 1440 × 2600px 확인.
- 아래쪽 sticky 제목이 합성 PNG에 남는지 픽셀 검사. 캡처 후 scrollY 280 복원과 fixed·sticky 원래 스타일 복원 확인.
- 편집 화면과 전체 페이지 PNG를 이미지 뷰어로 열어 육안 확인. 브라우저 page error 없음.
- `npm run package`: JavaScript 구문과 manifest 참조 파일 검사를 통과하고 ZIP 생성. 최초 ZIP의 확장 파일을 원본과 바이트 단위로 대조함. 공개용 ZIP에는 MIT LICENSE도 포함함.

재현 스크립트: `tests/model.test.js`, `tests/browser.mjs`. 최근 로컬 실행 증거는 git에서 제외한 `test-results/verification.json`, `marked.png`, `cropped.png`, `full-page.png`, `editor.png`에 있음.

## 발견 후 수정한 결함

1. CSS smooth scroll이 켜진 페이지에서 복원 스크롤이 애니메이션으로 진행됨. 예상 280 대신 831인 실패를 재현한 뒤 `behavior: instant`로 수정.
2. 모든 sticky 노드를 숨기면 첫 화면 아래의 제목이 캡처되지 않음. y1390 픽셀이 배경색으로 나오는 실패를 재현한 뒤 sticky를 정상 흐름에 임시 배치하고 캡처 후 스타일을 복원하도록 수정.

별도 리뷰 에이전트가 전체 runtime의 입력·메시지 출처·저장·합성·복원 흐름을 검토했고, sticky 결함 수정 후 재리뷰에서 추가 중요한 결함을 발견하지 않았음.

## 남는 사용 범위

검증은 로컬 정적 fixture와 이미지에 한정됨. 모든 사이트, 무한 스크롤, 가상 목록, 내부 스크롤 영역, DRM 영상은 검증하지 않음. 사용자 Chrome 설치 후 실제 사용 사이트에서 동작을 확인하면 됨. 지원 제한은 `README.md`에 명시함.

## v1.0.2 성능 개선 검증

2026-10-21, 현재 화면 PNG 재인코딩 제거·프레임 단위 그리기·클립보드 작업 및 PNG 결과 재사용을 적용함.

- `npm test`: 모델 10개와 렌더 작업 5개, 총 15개 통과. 프레임 요청 묶기·취소, 진행 중 PNG 생성 공유, 완료 결과 재사용, 수정 후 이전 작업 결과 격리, 용량 제한, 동기·비동기 오류 후 재시도를 확인함.
- `node tests/render-mutation.mjs`: 임시 사본에서 프레임 묶기·PNG 재사용·무효화를 각각 무력화하자 해당 회귀 테스트가 실패함. 원래 코드를 복구한 사본에서는 모두 통과함.
- `npm run test:browser`: 실제 별도 Chromium의 13개 검사 항목 통과, page error 없음. 120개 포인터 갱신이 한 번 그리기로 묶이고 포인터를 놓은 뒤 미리보기가 남지 않는지 확인함.
- 같은 PNG를 파일 저장 후 복사할 때 재인코딩하지 않음. 연속 Ctrl+C 여섯 번은 진행 중인 클립보드 쓰기 한 번을 공유함. 복사 실패 후 버튼이 다시 활성화되고 실제 쓰기 재시도가 성공함.
- 수정·자르기·실행 취소·다시 실행·이미지 교체 시 새 PNG 생성 확인. 새 이미지의 PNG 픽셀에 이전 사각형이 남지 않는지 검사함. 원본 해상도·잘린 해상도 및 기존 표시 기능·영속 저장도 확인함.
- 현재 화면 캡처에서 OffscreenCanvas PNG 재인코딩 횟수가 0임을 확인함. 같은 검사는 개선 전 코드에서 1회로 실패함. 전체 페이지 합성 PNG와 sticky 픽셀·스크롤 및 스타일 복원 검사도 통과함.
- 설치된 Google Chrome의 새 프로필에서 전후 각각 5회 실제 실행함. 클립보드 API는 실제 이미지 쓰기를 수행함. Windows 메모리는 프로세스 카운터를 읽었으며 JS heap 크기로 대신하지 않음. [전체 결과와 재현 방법](performance.md), [원시 결과](benchmarks/2026-10-21.json)에 조건·중앙값·변동 범위를 공개함.
- `npm run package`의 구문·매니페스트 검사를 통과함. v1.0.2 ZIP의 확장 파일 및 LICENSE 전체를 로컬 원본과 바이트 단위로 대조함.
- 코드 리뷰와 파일·프로필 접근 및 종료·삭제 범위의 보안 리뷰에서 중요한 추가 결함이 발견되지 않음. 측정 리뷰 지적에 따라 복사 시간에 동기 PNG 합성을 포함하고, 다음 프레임의 그리기 비용도 메인 스레드 작업 시간에 포함함.

v1.0.2 사용자의 기존 Chrome 프로필에서 직접 업데이트 후 사용한 결과는 아직 확인하지 않음. 위 검증은 별도 시험용 프로필 기준임.

## v1.0.4 버전 표시와 초기 그리기

2026-10-21. 팝업 하단에 `chrome.runtime.getManifest().version`으로 실제 버전을 표시함. 캡처·파일 로딩 시 같은 이미지를 연속 두 번 그리던 초기화 경로에서 한 번만 그리도록 수정함.

- 버전 요소가 없는 기존 코드에서 회귀 검사가 실패함을 확인함. 버전 표시를 추가한 뒤에는 초기 그리기 횟수가 2여서 두 번째 검사가 실패했고, 중복 그리기를 제거한 뒤 통과함.
- `npm test`: 모델·렌더 작업 15개 통과. `npm run test:browser`: 버전 표시를 포함한 14개 검사 항목 통과, page error 없음. 첫 이미지 그리기가 정확히 한 번인지 직접 검사함.
- 설치된 Google Chrome 155의 별도 headless 프로필에서 전후 각각 5회 캡처를 실행했고, 초기 그리기는 모든 실행에서 2회에서 1회로 줄었음. 팝업은 실제 도구 모음 클릭 대신 확장 URL을 별도 페이지로 열어 검사했으므로 사용자 Chrome의 메뉴 지연을 재현한 것은 아님.
- 전체 대기시간은 변동이 커서 개선으로 판단하지 않음. 이 릴리스는 메뉴가 느리게 열리는 문제의 원인까지 확인하거나 해결했다는 의미가 아님.
- 팝업 스크린샷에서 하단 `v1.0.4` 표시와 줄바꿈·버튼 배치를 확인함. 코드 리뷰에서 중요한 미해결 결함 없음.

## v1.0.5 사각형 자동 번호

2026-10-21. 사각형 도구 아래에 기본 켜짐인 자동 번호 체크박스를 추가함. 사각형과 기존 번호 shape를 같은 commit으로 추가해 한 번의 실행 취소·다시 실행과 한 번의 저장으로 처리함. 번호 추가 후의 개별 선택·이동·삭제는 기존과 같음.

- `npm test`: 기존 모델·렌더 작업 검사와 새 좌표 경계 검사를 포함한 18개 통과. 이미지 모서리, 역방향 드래그의 기준점, 자르기 좌표, 작은 이미지에 맞춘 반지름 조정을 검사함. 새 좌표 함수가 없는 기존 코드에서 먼저 실패함을 확인함.
- `npm run test:auto-number`: 설치된 Google Chrome의 별도 headless 프로필에서 7개 기능 경로 통과. 자동 번호 체크박스가 없는 기존 코드에서 먼저 실패함을 확인함. [원시 실행 결과](auto-number/v1.0.5.json)에 버전·브라우저와 검사 항목을 기록함.
- 자동 번호 기본값, 한 번 실행 취소·복원, 연속 번호와 수동 도구 혼용, 끈 상태의 박스 추가, 너무 작은 제스처 무시, 사용자 시작 번호·색상·크기, 새로고침 복원, 실제 클립보드 쓰기와 내보낸 PNG의 라벨 픽셀을 검사함. 잘라낸 이미지의 배치와 최대 번호 999 및 취소 후 번호 복원도 확인함.
- `npm run test:browser`: 기존 수동 도구·캡처·저장·복사 검사 14개 통과, page error 없음. 기존 수동 도구 검사는 자동 번호를 명시적으로 끄고 같은 동작을 검사함. 성능 측정 스크립트도 기존과 같은 사각형·수동 번호 부하를 유지하도록 자동 번호를 끔.
- 실제 화면에서 체크박스와 자동 번호 1·2의 배치를 확인함. 새 기능은 기존 렌더·저장 형식을 사용하며 권한을 추가하지 않음. 사용자 Chrome의 첫 메뉴 지연 개선을 주장하는 변경은 아님.
- 코드·보안 리뷰에서 중요한 미해결 결함 없음. 가이드 촬영 스크립트는 사각형 두 개의 자동 번호를 사용하도록 수동 번호 추가 단계를 제거함. ZIP의 전체 파일을 로컬 원본과 바이트 단위로 대조함.

## v1.0.3 연속 사용·다중 탭 검증

2026-10-21. 같은 캡처의 여러 편집 탭이 서로 저장을 덮어쓰는 문제와 오래된 캡처의 최근 편집이 정리되는 문제를 실제 Chrome에서 재현한 뒤 수정함. 저장 실패 후 파일 교체로 미저장 표시가 사라지는 문제도 재현 후 수정함.

- `npm run test:stability`: 설치된 Google Chrome의 별도 headless 프로필에서 전체 시나리오 통과. 세 편집 탭의 빠른 저장·실제 복사·새로고침, 긴 이미지 교체, 충돌 후 보관·복구와 명시적 폐기, 정리 시각 경계, 겹친 캡처·탭 전환 복원·유휴 worker 재시작을 확인함.
- 실제 실행 횟수·시나리오별 결과·수정 전 실패 기록은 [안정성 보고서](stability.md)와 연결된 JSON에 있음. `scripts/stability-report.mjs`가 통과 여부와 원시 수치를 확인하고 보고서를 생성함.
- `npm test`: 기존 모델·렌더 작업 테스트 15개 통과. `npm run test:browser`: 기존 13개 브라우저 검사도 통과, page error 없음. 기존 테스트의 원본 탭 조회는 종료될 수 있는 worker 대신 확장 페이지에서 수행하며 검사 전 worker를 깨움.
- 저장 충돌은 단일 IndexedDB 트랜잭션의 revision 비교로 감지함. 충돌 후 대기 중인 이전 저장도 거절되며, 다른 탭의 저장본과 로컬 작업을 함께 보호함. 로딩 중 문서 변경을 차단해 파일 교체 직전 저장 큐가 뒤늦게 늘어나지 않도록 함.
- 문서 변경·타임스탬프 갱신·정리는 기존 DB 버전에서 동작하며, 기존 revision 없는 문서와 updatedAt 없는 문서의 호환도 확인함. 코드·보안 리뷰에서 중요한 미해결 결함 없음.
- 패키지 구문·매니페스트 검사와 ZIP의 전체 원본 파일 대조를 통과함. 사용자의 기존 Chrome 프로필에 직접 업데이트한 결과나 24시간 실제 연속 실행 결과를 뜻하지 않음.

## v1.0.6 코드 검토 후 수정

2026-10-22. 초기 이미지 복원과 새 파일 열기 충돌, 마지막 캡처 겹침으로 인한 고정 헤더 손실, 정상 캡처를 중단하는 90초 복원 타이머, 화살표의 빈 영역 선택 오류를 수정함. [실행 결과](review/v1.0.6.json)에 브라우저·회귀 검사·안정성 시나리오를 기록함.

- 초기 복원과 파일 열기를 하나의 로딩 잠금으로 관리함. 첫 이미지 디코딩을 지연시켜도 다른 파일이 끼어들지 않으며, 이후 파일 교체·편집·새로고침이 같은 저장 대상을 유지함. 디코딩 실패 후 입력 잠금 해제와 새 파일 열기도 확인함.

## v1.2.1 원래 페이지에서 영역 선택

## v1.2.2 영역 캡처 코드 정리

2026-10-29. 중복된 페이지 스크립트 실행을 `executeInTab`으로 합치고, 선택 화면의 이벤트 정리를 `AbortController`로 통일함. 이미 종료한 선택은 늦은 콜백에서 다시 종료·포커스 복원하지 않도록 처리함. 함수 직렬화가 필요한 선택 UI는 같은 파일 안에 유지함.

PNG 인코딩을 기다리는 중 선택을 취소해도 저장·새 편집기 열기가 이어지던 경합을 재현 검사로 확인함. 변환 후 선택 상태를 다시 확인하도록 고쳤고, 취소 시 저장·새 탭 생성이 없는지 검사함. 이는 인코딩 대기 구간의 보완이며 DB 저장까지 원자적인 취소를 보장하는 변경은 아님.

리팩터링 전후 드래그·실제 PNG·취소·재시도·현재 화면·전체 페이지 캡처 검사를 통과함. 취소 후 원래 페이지의 스크롤 복구와 선택 상태 재사용 거부 검사도 추가함. 독립 코드·메시지 경계 검토를 마쳤음. [실행 결과와 패키지 대조](region/v1.2.2.json)에 검증 환경을 기록함.
